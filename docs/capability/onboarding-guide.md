# Onboarding Guide

> From a fresh checkout to the first managed multi-stage install.

This guide assumes you are using `quartzctl` through the `quartz` binary. The CLI can operate against any project that follows the `quartz.yaml` plus staged OpenTofu pattern.

## 1. Prerequisites

| Requirement | Notes |
|-------------|-------|
| `quartz` CLI | Install from releases, `go install`, or build from this repo |
| OpenTofu | Required for stage operations |
| Cloud credentials | AWS is the current cloud provider implementation |
| GitHub token | Needed when the target project uses GitHub source control or GitOps wiring |
| DNS/provider credentials | Needed only when the target project config uses those providers |
| Kubernetes access | Generated by `quartz login` after cluster creation |

For CLI development:

```bash
cd quartzctl
mise install
mise run build
./bin/quartz --version
```

For a target project:

```bash
quartz --version
quartz check
```

## 2. Start From The Minimal Sample

Use [docs/samples/minimal/quartz.yaml](../samples/minimal/quartz.yaml) as a small reference.

Minimum shape:

```yaml
name: myenv
tmp: ./out

dns:
  zone: quartz.example.com

aws:
  region: us-east-1

github:
  organization: mygithuborg

stage_paths:
  - stages

stages: {}
```

If `dns.domain` is omitted, quartzctl derives it as `<name>.<dns.zone>`.

## 3. Create Stage Directories

Stage directories use an ordered prefix and an id:

```text
stages/
  01-infrastructure/
    main.tf
  02-charts/
    main.tf
    stage.yaml
```

The folder `01-infrastructure` becomes stage id `infrastructure`. The numeric prefix sets the initial order. Dependencies in `stage.yaml` can adjust order so a stage always runs after the stages it needs.

Example `stage.yaml`:

```yaml
description: Application charts
dependencies:
  - infrastructure
providers:
  kubernetes: true
vars:
  vpc_id:
    stage:
      name: infrastructure
      output: vpc.vpc_id
checks:
  post_install:
    after: [apply]
    kubernetes:
      - name: my-release
        namespace: default
        kind: HelmRelease
        state: Ready
        timeout: 600
```

## 4. Configure Credentials

Common environment variables:

```bash
export AWS_ACCESS_KEY_ID=...
export AWS_SECRET_ACCESS_KEY=...
export AWS_DEFAULT_REGION=us-east-1

export GITHUB_USERNAME=...
export GITHUB_TOKEN=...
```

Supported credential aliases include Ironbank, GitHub, and Cloudflare variables. You can also pass a secrets YAML file:

```bash
quartz --secrets ./secrets.yaml check
```

## 5. Render And Inspect

Before the first install, render the final config:

```bash
quartz render --out ./out/quartz.generated.yaml
```

Check that:

- `dns.domain` is correct.
- `stage_paths` resolved to the intended folders.
- Stage ids and dependency order look right.
- Secrets are not committed to the repo.

## 6. Run The First Install

```bash
quartz install
```

For CI or unattended use:

```bash
quartz install --yes
```

If a stage fails after a transient issue, re-run:

```bash
quartz install --yes
```

To resume from a known stage:

```bash
quartz install --resume-from charts --yes
```

## 7. Validate

After a Kubernetes cluster exists:

```bash
quartz login
export KUBECONFIG=./out/kubeconfig
quartz info
```

For stage-level validation:

```bash
quartz tofu plan --stage infrastructure --init
quartz tofu output --stage infrastructure --init
```

## 8. Day-2 Basics

| Goal | Command |
|------|---------|
| Re-run convergent install | `quartz install --yes` |
| Resume from a stage | `quartz install --resume-from <stage> --yes` |
| Plan one stage | `quartz tofu plan --stage <stage> --init` |
| Apply one stage | `quartz tofu apply --stage <stage> --init` |
| Inspect state | `quartz tofu state list --stage <stage> --init` |
| Import missing resource | `quartz tofu import --stage <stage> ADDRESS ID --init` |
| Release stale lock | `quartz tofu force-unlock --stage <stage> LOCK_ID --init` |
| Full teardown | `quartz clean --yes` |

## Common First-Run Notes

- A missing `dns.zone` and `dns.domain` is a fatal config error.
- A stage without a numeric prefix can still load, but ordered prefixes make operations easier to reason about.
- `providers.kubernetes: true` on a stage means Kubernetes access is required for that stage.
- `quartz install` is designed to be re-run after partial failure.
- Keep generated files under `tmp` or `out` out of source control unless your program intentionally captures them as evidence.
